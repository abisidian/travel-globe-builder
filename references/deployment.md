# 部署与调用示例

## 复制给 AI 的提示词

### 创建完整项目

```text
使用 $travel-globe-builder，在 <新项目绝对路径> 创建完整旅行地球 Web 应用，项目名 my-travel-globe。使用暖色手绘风、独立可拖动猫狗、国家聚焦后展示省州和完整照片视频画廊，先带演示素材。安装依赖并验证 TypeScript、数据和生产构建；不要提交、推送或部署，交付启动方式和人工测试清单。
```

### 整理并导入真实素材

```text
使用 $travel-globe-builder，为 <项目绝对路径> 导入 <原片文件夹绝对路径> 下的旅行照片和视频。按国家、省州、可选城市整理，用已有目录、拍摄信息和我的行程确认归属。保留原片与现有相册，识别完全重复项，生成缩略图及兼容网页的完整视频，保留音轨，更新索引并验证。未知日期和地点列出待确认项，不编造；确定的素材可以先导入。不使用网盘，不公开、提交、推送或部署本次素材。最后报告导入、跳过、待确认和失败数量。
```

用户已有个人素材且不希望保留演示相册时，生成项目使用 `--empty`。用户没有授权删除已有演示数据时，不自动清空原项目。

### 准备并发布项目

```text
使用 $travel-globe-builder，为 <项目绝对路径> 准备部署到 <Vercel 或我的静态服务器>，目标 <预览环境/生产环境及项目或域名>。先读取 README，核对本次代码、允许公开的素材及目标账号，运行数据检查和构建，准备可审阅配置。输出目录为 dist，使用域名根路径。展示发布范围和目标，得到我确认后再发布；不擅自提交、推送、上传私人原片或开通收费服务。交付网址、版本、后续更新方法和人工验收 Todo，不主动执行 E2E。
```

若用户当前已经明确授权发布到指定目标与素材范围，遵循该授权，不用模板提示词重复要求相同确认。缺少发布目标时先询问；准备可独立进行的本地检查。

## 静态部署事实

- 使用 `npm ci`、`npm run build`，输出为 `dist`。本项目无需 API Key、数据库和网盘授权。平台构建不应重新运行演示素材或地图准备脚本。
- 在本地运行需要 FFmpeg 的数据检查；除非平台已明确安装 FFmpeg，否则平台只执行生产构建。
- Vercel 使用 Vite 预设，根目录为项目根目录、构建命令 `npm run build`、输出目录 `dist`，选择兼容项目 engines 的 Node.js。具体 CLI、账号权限、额度限制与部署设置在执行时核对 [Vercel 官方 Vite 文档](https://vercel.com/docs/frameworks/frontend/vite)。
- 模板 `/data/`、`/media/`、`/fonts/`、插画与光标是站点根路径；推荐根域名部署。GitHub Pages 仓库子路径需要完整修改资源 URL 和 Vite base，不能仅改一个 base 就宣称可用。按实际目标核对 [Vite 静态部署文档](https://vite.dev/guide/static-deploy.html)。
- `public` 内容进入静态产物，上传的展示照片和视频将随网站可访问；公有 Git 仓库中的文件也会公开。原片及带绝对路径的导入计划放在仓库外。用户新增本地素材后需要重新构建和发布，访客无法访问用户电脑里未发布的目录。
- 大视频按平台实际单文件、产物总大小和流量额度选择托管，不猜测限额；自建静态服务需正确 MIME 与 HTTP Range 才能拖动视频进度。不要通过删除视频、裁短或静音绕过体积限制。

部署后交付人工清单：地图与全部静态资源无 404、国家/省州选择正确、图片预览、视频播放/音频/拖动进度、全屏切换、手机布局。没有实际浏览器验证时清楚标为待人工验收。
