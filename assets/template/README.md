# 漫游记 · 旅行地球相册

用可拖动的地球收藏旅行照片和视频。默认按国家浏览，聚焦国家后展开省／州，再按城市筛选相册。支持照片放大、视频播放、键盘切换和手机布局，也有可以拖动、互动的小猫和小狗。

技术栈：React、TypeScript、Vite、react-globe.gl、Three.js。当前使用本地静态素材，不需要网盘授权、数据库或上传后台。

## 1. 安装与启动

### 环境准备

- 安装 [Node.js](https://nodejs.org/)：本项目的 Vite 7 要求 Node.js `20.19+` 或 `22.12+`；建议使用满足要求的 LTS 版本。npm 随 Node.js 安装。
- 安装 [Git](https://git-scm.com/downloads)，用于克隆项目。
- 整理媒体或运行数据检查时，需要 [FFmpeg](https://ffmpeg.org/download.html)，并确保 `ffmpeg` 和 `ffprobe` 都在 PATH 中。只启动应用、执行生产构建不需要它。

macOS 已安装 Homebrew 时，可以安装 FFmpeg：

```bash
brew install ffmpeg
```

Windows、Linux 可按照 FFmpeg 官方页面安装，完成后检查：

```bash
node --version
npm --version
git --version
ffmpeg -version
ffprobe -version
```

### 获取项目并启动

使用 Skill 生成项目后，在生成目录中安装和启动：

```bash
cd "<生成的项目目录>"
npm ci
npm run dev
```

如果已经有本地项目，直接在项目目录执行 `npm ci` 和 `npm run dev`。访问终端显示的地址，默认是 `http://127.0.0.1:5173/`；端口被占用时 Vite 会选择其他端口。

手机访问时，在同一局域网中运行 `npm run dev -- --host 0.0.0.0`，然后用手机打开 `http://电脑的局域网IP:终端显示的端口/`。

### 检查与构建

```bash
npm run typecheck
npm run check:data
npm run build
npm run preview
```

`check:data` 检查地区与城市关联、素材文件、尺寸、视频编码和时长，需要 FFmpeg。个人相册允许空相册、只有照片、只有视频或无城市分类，不要求凑齐演示场景。

`build` 包含 TypeScript 检查，生成 `dist/`。`preview` 用于本地查看构建结果，以终端显示的地址为准，不作为生产服务器。

## 2. 照片和视频放在哪里

原片可以放在电脑任意目录。建议将原片保存在仓库外，由 AI 复制选中的素材到项目，保留原片及其拍摄信息：

```text
旅行原片/                         ← 电脑上的独立目录
├── 中国/
│   └── 云南/
│       ├── 大理/
│       │   ├── 照片/
│       │   └── 视频/
│       └── 丽江/
│           ├── 照片/
│           └── 视频/
└── 日本/
    └── 北海道/
        └── 札幌/
            ├── 照片/
            └── 视频/
```

- 顺序固定为「国家 → 省／州／一级行政区 → 城市（可选）→ 照片或视频」。城市不明确时，照片／视频目录直接放在省州下面。
- 北京、上海等直辖市直接作为省级目录，不必重复创建同名城市层。没有省州的小国使用地图中对应的国家级地区 ID。
- 文件可保留手机原名。需要命名时，建议使用 `20251001-093015-01.jpg`，即拍摄日期、时间、序号；未知时间不编造。
- 先按明确的旅行行程、已有目录、拍摄时间和 GPS 分类；不能确定拍摄地点的文件留待确认，不凭风景外观强行归类。
- 只保留日期、地点相同但文件不同的素材；识别重复文件时使用文件哈希，不按相似文件名直接删除。

进入网页的展示文件放到 `public/media/`，可以继续按地区和城市分层：

```text
public/media/
├── albums/
│   └── 中国/云南/大理/
│       ├── 照片/20251001-093015-01.webp
│       └── 视频/20251001-100000-01.mp4
└── thumbs/
    └── CN-YN/dali/
        ├── 20251001-093015-01.jpg
        └── 20251001-100000-01.jpg
```

`public/` 是网站公开资源目录，构建时内容会进入 `dist/`；只放打算展示的素材。公有 GitHub 仓库中提交的文件也会公开，私人原片应继续留在仓库外。

## 3. 如何让素材显示在地球上

**应用目前不会自动扫描文件夹。** 除了复制文件，还需要更新 `src/data/travels.json`：`regions` 定义地区、城市和封面，`media` 定义每张照片或每段视频。可以手动编辑，也可以直接使用下一节的 AI 提示词。

地区 ID 必须匹配 `public/data/world.topo.json` 中 `objects.regions.geometries[].properties.id`，不要自己拼写一个新 ID。现有示例包含 `CN-YN`（云南）、`CN-SC`（四川）、`CN-ZJ`（浙江）、`JP-01`（北海道）、`US-CA`（加利福尼亚）。其他地区应查询地图实际数据。

以下展示一个地区、一个城市、一张照片和一段视频的完整索引结构。路径、日期、尺寸与视频秒数必须替换为真实文件对应的值：

```json
{
  "regions": [
    {
      "id": "CN-YN",
      "name": "云南",
      "country": "中国",
      "englishName": "YUNNAN, CHINA",
      "description": "云南旅行",
      "period": "2025.10.01 — 10.03",
      "cover": "/media/thumbs/CN-YN/dali/20251001-093015-01.jpg",
      "cities": [{ "id": "dali", "name": "大理" }]
    }
  ],
  "media": [
    {
      "id": "cn-yn-dali-20251001-093015-01",
      "regionId": "CN-YN",
      "cityId": "dali",
      "type": "photo",
      "title": "洱海日落",
      "date": "2025-10-01",
      "src": "/media/albums/中国/云南/大理/照片/20251001-093015-01.webp",
      "thumbnail": "/media/thumbs/CN-YN/dali/20251001-093015-01.jpg",
      "width": 2400,
      "height": 1600,
      "credit": "本人拍摄"
    },
    {
      "id": "cn-yn-dali-20251001-100000-01",
      "regionId": "CN-YN",
      "cityId": "dali",
      "type": "video",
      "title": "湖边散步",
      "date": "2025-10-01",
      "src": "/media/albums/中国/云南/大理/视频/20251001-100000-01.mp4",
      "thumbnail": "/media/thumbs/CN-YN/dali/20251001-100000-01.jpg",
      "width": 1920,
      "height": 1080,
      "duration": 12,
      "credit": "本人拍摄"
    }
  ]
}
```

录入规则：

- 每个媒体 `id` 唯一；`regionId` 指向 `regions` 中已有的地区。
- `cityId` 有值时，必须存在于该地区的 `cities` 中；不分城市时，删除媒体的 `cityId`，地区的 `cities` 使用空数组。
- `src`、`thumbnail`、`cover` 是网站路径，以 `/media/` 开头，对应磁盘上的 `public/media/`，不要填电脑绝对路径或 `public/` 前缀。
- `type` 只能是 `photo` 或 `video`。视频额外填写以秒计的 `duration`，`width`、`height` 填展示文件的真实像素尺寸。
- 照片展示文件使用 JPEG、PNG 或 WebP；视频使用 MP4、H.264、`yuv420p`，保留声音时使用 AAC，并启用 `faststart`。HEIC、RAW、MOV 和 Live Photo 可保留作原片，再转换为上述网页格式；Live Photo 的照片和短视频分开登记。
- 大图与缩略图分开保存。照片长边可控制在约 2400 像素，缩略图约 480 像素；视频单独提取封面，不能把整段视频当缩略图加载。
- 示例照片的地区、标题和日期是演示分类，不代表素材的真实拍摄位置。真实相册应使用自己的真实信息，保留第三方素材时继续保留署名和许可链接。

地图高亮与数量由索引中的媒体自动计算。新增素材通常只需修改 `public/media/` 和 `src/data/travels.json`，不必修改地图、地球组件或样式。

`npm run prepare:media` 专门准备现有在线示例素材，会重新生成缩略图、转码示例视频并改写索引，**不是个人照片导入命令**。真实素材请按上面的流程导入。地图数据已随项目提供，日常使用不需要执行 `prepare:map` 或 `prepare:land`。

### 使用内置素材导入器

先让 AI 根据真实目录、拍摄日期与地点创建项目外的计划 JSON：

```json
{
  "items": [{
    "source": "/你的原片目录/IMG_001.jpg",
    "regionId": "CN-YN",
    "city": {"id": "dali", "name": "大理"},
    "type": "photo",
    "date": "2025-10-01",
    "title": "洱海日落",
    "credit": "本人拍摄"
  }]
}
```

没有城市时省略 `city`，视频设置 `type: "video"`；尺寸、时长、网页路径由导入器生成。日期或地点未知时先确认，不猜测。

```bash
npm run import:media -- --project . --plan "/计划所在目录/import-plan.json"
npm run import:media -- --project . --plan "/计划所在目录/import-plan.json" --apply
```

第一条只读预检，第二条正式追加。完全相同的原片按内容哈希跳过；不会修改原片、替换既有相册或覆盖输出文件。原片不能解码时报告具体失败，本批索引不改写。转换保留完整视频和第一条音轨；HEIC/HEIF 支持取决于本机 FFmpeg，RAW 需先导出常见图片格式；HDR 素材需要另行校色。输出目录采用稳定国家、省州和城市 ID，界面仍使用中文名称。

## 4. 给 AI 的照片整理与导入提示词

在可以访问电脑文件和项目目录的 AI 编程助手中使用，将两个路径替换成自己的真实路径。它需要实际读取文件，单纯粘贴到无法访问本机文件的聊天窗口不会完成导入。

```text
请把我的真实旅行照片和视频整理并导入 travel-ball 项目。

项目路径：<项目的绝对路径>
原片路径：<旅行原片文件夹的绝对路径>
本次导入范围：<例如：中国/云南，或该目录下全部素材>
导入方式：追加到现有相册，保留现有示例；除非我明确要求，否则不替换和删除。

先读取项目 README.md、src/types.ts、src/data/travels.json 及地图中的实际地区 ID。
1. 读取原片目录、EXIF/GPS、真实拍摄时间和视频信息，按国家 → 省州 → 可选城市分类。以已有目录和明确的拍摄信息为依据，地点或日期无法确认时列出待确认文件并询问我，不根据景物外观编造。继续处理不依赖这些答案的文件。
2. 不移动、删除或覆盖原片。使用哈希识别完全重复文件，仅跳过重复导入；不要擅自删除连拍或相似照片。
3. 将网页展示副本放进 public/media/albums/国家/省州/城市/照片或视频/，无城市时省略城市层；缩略图放进 public/media/thumbs/对应地区和城市/。
4. 按需转换 HEIC/RAW/MOV，生成浏览器兼容的图片和 MP4（H.264、yuv420p、AAC 音频、faststart）。展示副本正确处理旋转方向，保持比例，照片长边约 2400 像素且不放大小图，缩略图约 480 像素；不裁短视频、不主动去除声音。无法解码的文件保留原片并单独报告。
5. 用 FFprobe 或等效工具读取输出文件的真实尺寸和时长。视频生成独立封面，照片生成独立缩略图。新媒体 ID 必须唯一，再次执行同一批素材时避免重复导入。
6. 更新 src/data/travels.json 的地区、城市、封面、时间范围和媒体。使用地图实际存在的地区 ID；素材类型明确区分 photo/video；路径以 /media/ 开头；只添加具有有效素材的地区和城市。未知信息不要写成虚构值。
7. 先生成明确的导入计划 JSON，用 npm run import:media -- --project . --plan <计划文件> 预检，在已授权范围内加 --apply 导入。优先使用内置脚本，不重复实现转码和索引逻辑；不运行示例素材准备命令 prepare:media。运行 npm run typecheck、npm run check:data 和 npm run build。如果个人数据不再满足“多城市、无城市、纯照片、纯视频”的示例覆盖要求，只调整这些示例覆盖断言，保留文件、关联、尺寸、时长、编码和地图检查。
8. 不写 UI 单元测试，不主动执行 E2E，不提交、不推送、不部署。函数和关键逻辑添加中文注释。最后报告成功/跳过/待确认/失败数量、修改的文件及受影响的 UI，并给出人工测试 Todo。
```

## 5. 部署方法

这是静态应用，可以把 `dist/` 放到静态托管平台或已有网站服务器上。部署后的照片和视频来自托管平台上的展示副本，访客不能通过网站读取你电脑上未发布的原片。新增本地素材后需要重新构建和发布。

以 [Vercel 的 Vite 部署](https://vercel.com/docs/frameworks/frontend/vite) 为例，代码和允许公开的展示素材推送到 GitHub 后，在 Vercel 导入该仓库并核对：

| 配置 | 值 |
| --- | --- |
| Framework Preset | Vite |
| Root Directory | 项目根目录（`.`） |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | 平台支持且满足上述版本要求的版本 |
| 环境变量 | 当前应用无需设置 |

`check:data` 需要 FFmpeg，普通托管构建环境通常未预装；可在本地完成检查，平台仅执行 `npm run build`。不要在平台构建阶段重新下载示例素材或重建地图。

当前资源使用 `/data/`、`/media/`、`/fonts/` 等站点根路径，适合部署在域名根目录。若部署到 GitHub Pages 的 `/travel-ball/` 子路径，必须同时检查 Vite `base`、地图请求、样式资源和素材索引中的路径，不能只修改一个 `base` 就假定全部可用。

大视频先核对托管平台的单文件、部署体积和流量限制。自建静态服务需返回正确的媒体类型，并支持视频字节范围请求（HTTP Range），以便拖动播放进度。

### 给 AI 的部署提示词

```text
请协助部署 travel-ball 静态旅行相册。

项目路径：<项目绝对路径>
GitHub 仓库：<用户为本项目选择的仓库；未关联则说明>
部署平台：<Vercel，或我的静态服务器>
部署目标：<预览环境或生产环境；已有项目名称/域名，没有则明确写新建>

先读取 README.md、package.json 和 vite.config.ts，检查 Git 远程地址及工作区，确认将发布的版本和素材范围。
1. 检查 Node.js、npm、必要时的 FFmpeg；使用锁文件安装依赖。先核对 public 中所有拟公开的照片、视频和索引，不把原片目录、账号授权、Token、.env 或本机配置加入部署包。需要我选择发布范围时先列出清单。
2. 在本地运行 npm run typecheck、npm run check:data 和 npm run build，修复本次部署相关的问题。保持现有手绘 UI、地球交互及媒体分类，不增加后端或网盘接入，不写 UI 单元测试、不主动执行 E2E。
3. 使用静态部署配置：npm ci 安装，npm run build 构建，dist 为输出目录。优先使用域名根目录；若目标必须是子路径，修正并检查全部资源路径，不能只改 Vite base。
4. 在真正发布前，展示目标账号/平台、仓库与版本、素材数量、公开访问范围和可能的收费选项；需要开通付费服务或上传额外私人文件时单独询问。先完成可本地核对的构建和配置，再让我确认发布。不要擅自提交或推送代码。
5. 得到发布确认后，使用我已有的平台连接或浏览器登录完成发布，不索取明文密码，不把授权信息写进源码。若远端缺少本次代码，明确说明并等待我授权提交/推送，不部署错误版本。
6. 发布完成后交付实际网址、平台项目链接、发布版本、后续更新方式，以及地球加载、图片预览、视频播放/拖动进度、手机布局的人工测试 Todo。明确区分构建通过、已发布和已人工验证的状态。
```

## 6. 人工验收 Todo

- [ ] 地球能旋转、缩放、重置，拖拽不会误选；只有聚焦国家展示省州。
- [ ] 新地区正确高亮，省州、城市与照片／视频数量匹配。
- [ ] 城市筛选和照片／视频页签正常，无城市素材出现在“全部”。
- [ ] 缩略图清晰，打开原图比例正确，可放大与前后切换。
- [ ] 视频能播放、保留应有音频，可拖动进度；关闭或切换时停止播放。
- [ ] 关闭查看器后保留相册筛选和滚动位置，手机布局可用。
- [ ] 部署后地图、字体、插画和全部媒体加载正常，没有资源 404。
